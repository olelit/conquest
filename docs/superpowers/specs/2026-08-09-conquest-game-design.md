# Conquest: Игровая механика (игрок + ИИ) через WebSocket — дизайн

Дата: 2026-08-09

## Цель

Добавить в существующий docker-стек (Postgres + Node TS + Vue TS) игру для одного игрока против простого ИИ: захват гексов, экономика очков, битвы за гексы с 1:1 контр-вложением. Всё взаимодействие с картой — через WebSocket (единый URL, без CORS). Работа без git-операций.

## Правила игры

### Экономика
- Игровой тик = 1 секунда (серверный setInterval).
- Доход игрока: +1 очко за каждый свой гекс за тик.
- Максимум очков: `1000 + (число гексов × 50)`. Старт: 1000 очков, лимит 1000.
- Очки не могут превышать лимит (лишнее теряется).

### Захват нейтрального гекса
- Нейтральный гекс (без владельца и без битвы) захватывается за стоимость по типу местности:
  - grass (равнина) 200, desert (пустыня) 250, forest (лес) 300, water (вода) 400, mountain (горы) 500.
- Захват разрешён только если гекс соседний с территорией игрока (axial-соседство, см. ниже).
- **Первый гекс каждой стороны — бесплатный и любой** (не требует соседства, стоимость 0). Игрок с 0 гексов может захватить любой нейтральный гекс бесплатно. То же для ИИ.
- **Нейтральный гекс, соседний с территорией соперника, захватывается не мгновенно, а через битву**: захват стартует битву, где атакующий — захватчик, `attack_investment` = уплаченная стоимость (0 для бесплатного первого), `battle_progress` = 0. Соперник может вступить в эту битву обороняющимся (см. Битвы, defend), если гекс соседний с его территорией.
- Если битва за нейтральный гекс не возникла (не соседний с соперником) — захват мгновенный.

### Соседство (axial q, r)
Соседи гекса (q, r): (q+1, r), (q−1, r), (q, r+1), (q, r−1), (q+1, r−1), (q−1, r+1). Сосед за пределами поля (q ∉ 0..15, r ∉ 0..11) не существует — соседство с ним невозможно.

### Битвы
- Атаковать можно только гекс, принадлежащий сопернику, и только соседний со своей территорией.
- Начало атаки: игрок вкладывает ≥1 очко (`attack`). Гекс становится спорным: `attacker_id` = атакующий, `attack_investment` += вложенное (списывается из очков сразу).
- Спорным может быть и нейтральный гекс (см. Захват нейтрального гекса): `attacker_id` = захватчик, `defender_id` = NULL до тех пор, пока соперник не вступит.
- Обороняющийся может контрить вложением `defend` 1:1: `defense_investment` += вложенное (списывается сразу). `defender_id` фиксируется при первом вложении в оборону.
  - Для гекса с владельцем: обороняющийся — только владелец.
  - Для нейтрального спорного гекса: обороняющимся может стать соперник атакующего, только если гекс соседний с его территорией.
- Шкала борьбы: `battle_progress` (float, −1..1). Перевес `net = attack_investment − defense_investment`.
- Каждый тик: `battle_progress += (net / стоимость_гекса) × 0.1`, с отсечкой по ±1. Пока перевес на стороне атакующего — шкала растёт («гекс постепенно переходит»), на стороне обороняющегося — падает.
- Разрешение:
  - `battle_progress ≥ 1` — атакующий захватывает гекс: владелец = атакующий, битва сбрасывается, **атакующий получает свои вложения обратно** (attack_investment возвращается в очки), **вложения обороняющегося сгорают**.
  - `battle_progress ≤ −1` — побеждает оборона: **обороняющийся получает свои вложения обратно**, **вложения атакующего сгорают**. Если гекс был с владельцем — он остаётся у владельца (атака отбита); если гекс был нейтральным — **обороняющийся становится его владельцем** (победитель забирает гекс).
- Оба игрока могут доливать вложения в активную битву в любой момент (если хватает очков).
- Атаковать свой гекс или гекс, уже атакуемый соперником, нельзя; можно доливать в свою же атаку.

### ИИ (простой, один ход за тик, приоритеты сверху вниз)
1. **Оборона**: если любой гекс ИИ в битве (ИИ владелец ИЛИ атакующий на нейтральном спорном гексе) — вложить столько, чтобы сравнять перевес (A − D), насколько хватает очков (минимум 1, если перевес у соперника).
2. **Оспорить захват**: если нейтральный гекс в битве, где атакующий — игрок, и гекс соседний с территорией ИИ — вступить обороняющимся (вложить сравнение перевеса, насколько хватает очков).
3. **Рост**: если есть нейтральные соседние гексы, которые ИИ может себе позволить — захватить самый дешёвый (если он соседний с территорией игрока — захват станет спорным, игрок может вступить).
4. **Атака**: если нечего захватывать ИЛИ у игрока гексов больше, чем у ИИ — атаковать самый дешёвый соседний гекс игрока, вложив min(доступные очки, стоимость гекса).
5. Иначе — ждать.

### Победа
- Игрок, контролирующий **≥ 97 гексов** (больше половины из 192), побеждает. Обоим игрокам приходит состояние с `winner`, все игровые действия блокируются, фронт показывает баннер.

## Данные (Postgres)

- Новая таблица `players(id serial PK, name text NOT NULL, points int NOT NULL DEFAULT 1000, is_ai boolean NOT NULL DEFAULT false)`.
  При старте, если таблица пуста — вставить двух игроков: (name `player`, is_ai false) и (name `ai`, is_ai true). Идемпотентно.
- `hexes` расширяется колонками (миграция идемпотентная, ADD COLUMN IF NOT EXISTS):
  - `owner_id int NULL REFERENCES players(id)` — NULL = нейтральный
  - `attacker_id int NULL REFERENCES players(id)` — NULL = битвы нет
  - `defender_id int NULL REFERENCES players(id)` — сторона обороны (для гексов с владельцем = владелец; для нейтральных спорных — вступивший соперник); NULL пока оборона не вложилась
  - `attack_investment int NOT NULL DEFAULT 0`
  - `defense_investment int NOT NULL DEFAULT 0`
  - `battle_progress double precision NOT NULL DEFAULT 0`
- Инициализация поля при первом старте: как раньше (16×12, случайный террейн) + все владельцы NULL.

## Протокол WebSocket (`/ws`, единый URL через прокси)

### Сервер → клиент
- При подключении и после каждого тика/действия: `{ "type": "state", "game": { "players": [ { "id", "name", "points", "hexCount", "isAi" } ], "winner": <id|null>, "hexes": [ { "q", "r", "terrain", "ownerId", "attackerId", "defenderId", "attackInvestment", "defenseInvestment", "battleProgress" } ] } }`
- На невалидное действие: `{ "type": "error", "message": "..." }` (только этому клиенту).

### Клиент → сервер
- `{ "type": "capture", "q": 5, "r": 3 }`
- `{ "type": "attack", "q": 5, "r": 3, "points": 300 }`
- `{ "type": "defend", "q": 5, "r": 3, "points": 300 }`

### Валидация действий (сервер)
- capture: гекс нейтрален и без битвы; игрок имеет 0 гексов (бесплатно, любой) ЛИБО гекс соседний и очки ≥ стоимость.
- attack: гекс принадлежит сопернику и соседний; битва отсутствует (или её ведёт сам игрок — долив); points ≥ 1; points ≤ очки игрока.
- defend: битва активна (attacker_id не NULL и не равен игроку); игрок имеет право обороны — гекс принадлежит игроку, ЛИБО гекс нейтральный и соседний с территорией игрока (вступление в спор о нейтральном гексе); points ≥ 1; points ≤ очки игрока.
- Все действия: игра не окончена (winner NULL).
- Невалидное действие: ошибка клиенту, состояние не меняется.

### Переподключение
- Клиент ретраит коннект с бэкоффом (1с, 2с, 4с, ... до 10с, бесконечно).
- При каждом коннекте сервер шлёт полное состояние — рестарт API/сеть не теряют игру.

## Тик-движок (1 сек, в API-процессе)

1. Доход: для каждого игрока `points = min(points + hexCount, 1000 + hexCount × 50)`.
2. Битвы: обновить `battle_progress` для всех спорных гексов; разрешить достигшие ±1 (захват/отбой, возвраты вложений) — всё в одной транзакции.
3. Один ход ИИ (см. ИИ).
4. Проверка победы (≥97 гексов) → `winner`.
5. Рассылка полного состояния всем подключённым клиентам.

## Фронтенд (Vue)

- `src/api.ts` — WS-клиент: подключение, бэкофф-реконнект, send-хелперы (capture/attack/defend), обработка `state` и `error`.
- `src/App.vue` — держит `GameState` (ref), подключается на mount; рендерит HUD, поле, панель действий, баннеры (победа, разрыв соединения, ошибка действия).
- `src/components/HexMap.vue` — цвета: нейтральный = террейн (как сейчас); гекс игрока = синяя тонировка; гекс ИИ = красная тонировка; спорный гекс = террейн + полоса `battle_progress` (заливка сверху вниз, цвет атакующего) + числовые вложения. Hover-обводка остаётся. Клик по гексу — событие наружу с координатами.
- `src/components/Hud.vue` — очки/лимит, доход за сек (число гексов), счёт гексов обеих сторон.
- `src/components/ActionPanel.vue` — появляется при выборе гекса: тип действия (захват N очков / атака с суммой / защита с суммой / недопустимо — с причиной), кнопка выполнения.
- Обновление состояния — только по WS (никакого polling).

## Обработка ошибок

- Невалидное действие → `{type:'error', message}` клиенту, состояние не меняется; фронт показывает сообщение.
- Обрыв соединения → баннер «Переподключение…», реконнект с бэкоффом.
- Ошибка записи в БД в тике → лог, тик пропускается (состояние в БД консистентно, т.к. мутации в транзакциях).

## Критерии приёмки

1. `docker compose up` → на `http://localhost:5173` видно поле; HUD с очками 1000/1000 и счётом гексов.
2. Клик по нейтральному гексу (первый ход) — захват бесплатно, гекс синеет.
3. Последующие захваты — только соседние, списывается стоимость по террейну.
4. ИИ захватывает соседние гексы (красные), защищает свои и оспаривает захват нейтрального гекса у своей границы.
5. Атака на гекс ИИ: шкала борьбы ползёт вверх; ИИ контрит; при перевесе атакующего ≥100% гекс переходит (вложения победителя возвращаются), при отбое — сгорают вложения атакующего.
6. Захват нейтрального гекса у границы ИИ становится битвой: ИИ вступает, победитель забирает гекс.
7. Очки копятся каждый тик и не превышают лимит 1000+гексы×50.
8. Обновление состояния в браузере — без перезагрузки страницы (только WS).
9. Перезапуск `docker compose restart api` — игра продолжается, клиент переподключается.
10. Баннер победы при ≥97 гексов, действия блокируются.
