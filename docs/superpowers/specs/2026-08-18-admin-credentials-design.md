# Дизайн: смена логина/пароля админки в отдельной вкладке

Дата: 2026-08-18

## Проблема

Логин/пароль админки задаются только через env-переменные
(`CONQUEST_ADMIN_USER`, `CONQUEST_ADMIN_PASSWORD`, `CONQUEST_ADMIN_SECRET`)
и читаются при старте (`config.ts`). Изменить их на лету нельзя.

Требуется: в админ-панели отдельная вкладка, где можно сменить логин и пароль.
Новые креды должны переживать рестарт.

## Решение

Хранить креды в PostgreSQL. При старте сидер автоматически создаёт
запись из оригинальных env-кредов, если её ещё нет. Если запись уже есть —
БД-версия сохраняется и не перезаписывается env.

## Хранение и сидер

Новая таблица `admin_credentials`, одна строка (id = 1):

| колонка | тип | описание |
|---|---|---|
| `id` | int, PK | всегда 1 |
| `username` | text | логин админа |
| `password_hash` | text | scrypt-хэш пароля с солью |
| `session_secret` | text | случайный секрет для подписи сессионных токенов |

Сидер запускается в `initDb()` (паттерн `PlayersRepository.migrate`):
- если строки нет — создаём с логином/паролем из `config.adminUser`/`config.adminPassword`,
  генерируем случайный `session_secret`;
- если строка есть — ничего не делаем.

## Авторизация (переезд с env на БД)

- `authAdmin(username, password)` сверяет логин и scrypt-хэш из БД
  (вместо HMAC от env-пароля).
- Сессионные токены подписываются `session_secret` из БД
  (вместо `config.adminSecret`). Функции `signToken`/`verifyToken` не меняются,
  меняется только секрет.
- `adminSession` и `requireAdmin` становятся async: нужен lookup секрета из БД.
  При ошибке БД — ответ 503.
- env-переменная `CONQUEST_ADMIN_SECRET` после переезда для авторизации не нужна.

## Инвалидация сессий

При смене логина или пароля генерируется новый `session_secret` —
все старые токены (включая другие вкладки) перестают работать сразу.

## API

`POST /api/admin/credentials` (защищённый маршрут):

```json
{
  "currentPassword": "...",
  "newLogin": "новый_логин (необязательно)",
  "newPassword": "новый_пароль (необязательно)"
}
```

- `currentPassword` обязателен и должен совпадать с текущим паролем;
- меняется хотя бы одно из полей `newLogin`/`newPassword`;
- при успехе — обновление БД и ротация `session_secret`;
- ответ: `{ ok: true }`; ошибки: 401 (неверный текущий пароль),
  400 (пустой/одинаковый новый логин или пароль), 409 (новый логин совпадает со старым).

## UI (отдельная вкладка)

В `server/public/admin.html` добавляется навигация по вкладкам:
«Обзор» (текущий дашборд) и «Аккаунт».

Вкладка «Аккаунт»:
- текущий логин (только чтение);
- поле текущего пароля;
- поле нового логина;
- поле нового пароля;
- кнопка «Сохранить».

После успешной смены — принудительный выход на форму логина
(сессии инвалидированы). Ошибки выводятся под формой.

## Тестирование

- сидер создаёт юзера при отсутствии и не трогает существующего;
- `authAdmin`: верный/неверный пароль, scrypt-хэш;
- смена кредов обновляет БД и ротирует `session_secret`;
- старый токен после смены отклоняется;
- API `/api/admin/credentials`: валидация входных данных и ответы об ошибках.
