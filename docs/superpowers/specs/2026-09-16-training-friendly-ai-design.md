# Дизайн: дружелюбный ИИ в режиме обучения

Дата: 2026-09-16. Проект: Conquest.

## Контекст и цель

В режиме обучения (`Room.training = true`, флаг прокидывается из
`createSolo(..., training)` по кнопке «Обучение», `App.vue` →
`sendStartSolo('tutorial', 1, 'easy', true)`) ИИ сейчас ведёт себя как в
обычной игре:

- первую клетку выбирает **подальше** от врага (`ai.ts:174-183`), поэтому
  этап обучения «Атака» не может начаться: рядом с игроком нет вражеского
  гекса;
- объявляет игроку войну первым (`ai.ts:220`), может атаковать и выбить
  игрока, а при большинстве гексов автоматически побеждает
  (`rooms.ts:442-443`).

Цель: в обучении игрок не может проиграть, а ИИ становится соседом, чтобы
работали этапы «Атака» и «Защита».

Требования:

1. ИИ не объявляет игроку войну первым и вообще не инициирует дипломатию.
2. ИИ не атакует гексы игрока, пока они в мире; если игрок сам объявил
   войну — ИИ отвечает атаками (этап «Защита» в `training.ts:100-107`
   требует, чтобы гекс игрока был атакован).
3. ИИ не может победить: лимит гексов и неприкосновенная столица игрока.
4. Первая клетка ИИ — по соседству с игроком.

## Поведение ИИ в обучении

### 1. Ожидание и первая клетка рядом с игроком

Пока у игрока (не-ИИ, не выбывший) нет ни одного гекса, ИИ не делает
действий. Как только гекс появился, ИИ выбирает свободный (ownerId === null,
attackerId === null), не водный гекс, соседний с любым гексом территории
игрока; при нескольких кандидатах — минимальная стоимость террейна, при
равенстве — порядок по `(q, r)`. Если кандидатов нет — ждёт (возвращает
null); после расширения игрока кандидат может появиться.

Первый гекс ставится сразу как владение, минуя правило «сначала объяви
войну» (`rules.ts:141`, `hasPeacefulNeighbor`) и бой у границы
(`rules.ts:240-247`), бесплатно — как первый гекс человека
(`applyCapture`, `isFirst` → cost 0). Для этого — отдельная функция
`placeFirstHex`.

### 2. Дипломатия

В обучении `handleAiDiplomacy` не вызывается: ИИ никогда не объявляет войну
и не шлёт предложения мира/союза. Предложения игрока обрабатываются как
обычно (`aiAcceptsProposal`, `respondToProposal`), в том числе
`propose-peace` от игрока и `observed`-этап «Дипломатия».

### 3. Лимит гексов

Захват нейтральных гексов запрещён, когда `hexCount(aiId) >=
config.trainingAiMaxHexes` (env `CONQUEST_TRAINING_AI_MAX_HEXES`, по
умолчанию 5). Ответные атаки и защита лимитом не ограничены. Обычный режим
не меняется.

### 4. Ответные атаки и защита

Ветки защиты и атаки `chooseAiAction` работают как раньше: атака возможна
только по игроку, с которым война (её объявляет игрок). Отдельного
«разрешения» не требуется.

### 5. Неприкосновенность столицы игрока

- `tickBattles` получает опцию `canCapture(hex)`. В обучении Room передаёт
  колбэк: столица игрока — `false`. Если бой за столицу выигран, результат
  становится ничьей (`winnerId: null`), гекс остаётся игроку, бой
  сбрасывается. Прямой захват столицы ИИ невозможен.
- Страховка от анклава: в `handlePlayerLoss` для человека в обучении
  `eliminateIfCapitalLost` не вызывается; если столица уже сменила
  владельца (редкий случай `applyEnclosure`), гекс возвращается игроку.
- Страховка победы: в `updateWinner` в обучении ИИ никогда не получает
  `winnerId` (ни по большинству, ни как последний оставшийся). Победа
  игрока не ограничивается.

## Изменения по файлам

### `server/src/ai.ts`

```ts
export interface AiOptions {
  training?: boolean;
  maxHexes?: number;
}
export function chooseAiAction(
  state: GameState,
  aiId: number,
  opts: AiOptions = {},
): AiAction | null;
```

- `chooseFirstCapture(state, aiId, training)`: при `training` — алгоритм из
  п. 1 (человек = `!p.isAi`, `hexCount > 0`); без него — текущий алгоритм
  без изменений.
- Ветка захвата нейтралов: при `training && hexCount >= maxHexes` не
  выбирается (функция продолжает поиск защиты/атаки, иначе null).

### `server/src/rules.ts`

```ts
export function placeFirstHex(state: GameState, playerId: number, q: number, r: number): boolean;
export interface TickBattlesOptions {
  canCapture?: (hex: HexState, attackerId: number) => boolean;
}
export function tickBattles(state: GameState, opts: TickBattlesOptions = {}): BattleResult[];
```

- `placeFirstHex`: гекс свободен (без владельца и атакующего) → ownerId =
  playerId, fortress = false, `player.capital ??= {q, r}`, без списания
  очков; возвращает `true`. Иначе `false`.
- `tickBattles`: в ветке `battleProgress >= CAPTURE_TICKS`, если
  `opts.canCapture && !opts.canCapture(hex, hex.attackerId)` — результат
  `{ winnerId: null }` (ничья), `resetBattle(hex)`, без смены владельца.

### `server/src/config.ts`

`trainingAiMaxHexes: number('CONQUEST_TRAINING_AI_MAX_HEXES', 5)`.

### `server/src/rooms.ts`

- `tick()`: `rules.tickBattles(state, this.training ? { canCapture: (hex) =>
  !this.isHumanCapital(hex) } : {})`; `handleAiDiplomacy` вызывается только
  при `!this.training`.
- `chooseAiAction(state, player.id, { training: this.training, maxHexes:
  config.trainingAiMaxHexes })`.
- `applyAiAction`, case `capture`: при `this.training && hexCount === 0` —
  `rules.placeFirstHex` (плюс запись статистики действия, как у обычного
  захвата), иначе существующая ветка.
- Новый приватный `isHumanCapital(hex)`: координаты совпадают с
  `capital` живого игрока `!isAi`.
- `handlePlayerLoss`: при `this.training` и человеке — вернуть столицу
  игроку при смене владельца, не выбивать игрока
  (`eliminateIfCapitalLost` не вызывается), но выполнить обычную ветку
  `applyCut` (отрезанные фрагменты становятся нейтральными), как при
  потере не-столичного гекса.
- `updateWinner`: при `this.training` не назначать победителем ИИ.

## Обработка ошибок

- Нет подходящего соседа для первого гекса ИИ — ИИ ждёт, ошибок нет.
- `placeFirstHex` вернул `false` (гекс занят) — действие пропускается молча;
  на следующем интервале ИИ выберет заново.
- В обычном режиме поведение не меняется: все новые опции по умолчанию
  выключены.

## Тестирование

- `server/test/ai.test.ts`:
  - обучение: игрок без гексов → null;
  - обучение: первый гекс — свободный не водный сосед игрока; при
    нескольких — дешевейший;
  - обучение: при лимите гексов нейтралы не захватываются, но ответная
    атака/защита выбирается;
  - без обучения поведение прежнее (существующие тесты).
- `server/test/rules.test.ts`:
  - `placeFirstHex` ставит владельца и столицу без боя и списания очков;
  - `tickBattles` с `canCapture: () => false` на выигранном бою за столицу —
    ничья, владелец не меняется.
- `server/test/rooms.test.ts` (интеграционно, `new Room(..., training)`):
  - ИИ не действует, пока у игрока нет гекса; после первого гекса игрока
    первый гекс ИИ — его сосед и принадлежит ИИ (не бой);
  - в обучении ИИ не объявляет войну (журнал/дипломатия) ни разу за много
    тиков;
  - после объявления войны игроком ИИ атакует гекс игрока;
  - бой за столицу игрока не заканчивается захватом (ничья);
  - при лимите гексов ИИ не расширяется по нейтралам;
  - обычный режим не сломан (существующие тесты).
- Web: изменений нет; `npm run build` в `web` (vue-tsc) — как проверка, что
  ничего не задето.
