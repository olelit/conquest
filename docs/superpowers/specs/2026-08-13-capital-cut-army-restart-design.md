# Дизайн: армия в %, перезапуск, столица, отрезание территории

Дата: 2026-08-13

## Обзор

Четыре связанных изменения геймплея и UI:

1. Армия задаётся в процентах от текущих очков игрока, а не в абсолютных единицах.
2. В меню появляется пункт «Перезапустить игру» (только в играх против компьютера).
3. Первый захваченный гекс игрока — его столица. Потеря столицы = поражение игрока.
4. Отрезание территории: захват «шейки» (единственной связующей клетки) делает отрезанную часть без столицы нейтральной.

## 1. Армия в процентах

### Текущее поведение

- `App.vue`: `army = ref(200)` — абсолютное число очков. `onHexClick` шлёт `send = max(1, min(army, points))` в `sendAttack/sendCapture`.
- `ArmyBar.vue`: поле ввода (число), кнопки ±50, подпись «доступно X/Y».
- `Hud.vue`: показывает `points - army` как доступный резерв.

### Новое поведение

- `army` хранится как **процент** от текущих очков игрока: `number` 0–100.
- В момент действия (клик по гексу) конвертация: `send = floor(points * army / 100)`, `send = max(1, send)`, если `points >= 1`.
- `isCapturable` в App.vue использует ту же конвертацию для проверки бюджета.
- ArmyBar: поле ввода с суффиксом `%`, кнопки ±5%, подпись «доступно X/Y» остаётся абсолютной.
- HUD: резерв игрока = `floor(points * army / 100)`, вычитается из `points`.
- Watch `army > points` в App.vue больше не нужен (процент всегда ≤ очков); удалить.
- Сервер не меняется: получает абсолютные значения как раньше.

## 2. Перезапуск игры

### Сервер

- Новый тип сообщения `restart` (ws.ts → RoomManager).
- Доступно только в комнатах с `aiMode === true` (соло).
- `Room.restart()`:
  - регенерирует карту (`generateMap(mapType)`);
  - сбрасывает `state` полностью (игроки с `BASE_POINTS`, без владений, без столиц);
  - `status` остаётся `playing`, `paused = false`, `finishedAt = null`;
  - сброс `aiLastActionAt`;
  - лог «Игра перезапущена».
- Проверка: комната существует, `aiMode`, идёт игра (`status === 'playing'`).

### Клиент

- `api.ts`: `sendRestart()`.
- Burger-меню (App.vue): пункт «Перезапустить» виден только при `room.aiMode`; перед отправкой `window.confirm`.

## 3. Столица и поражение

### Правила (server/src/rules.ts)

- `HexState.isCapital: boolean` (по умолчанию `false`).
- При `applyCapture`/завершении битвы: если у игрока-победителя владений не было и это его первая клетка — она становится `isCapital = true` (для первого захвата; битва не нужна — первый гекс захватывается мгновенно).
- Проверка потери столицы: после любой смены владельца клетки, если клетка была `isCapital` и теперь принадлежит другому — владелец выбывает.

### Выбывание (elimination)

- `PlayerState.eliminated?: boolean`.
- При выбытии территория проигравшего:
  - **90%** — все его гексы становятся нейтральными (`ownerId = null`);
  - **10%** — делится на новых ИИ-игроков: `k = clamp(round(hexes/10), 2, 5)`; каждому достаётся по `floor(hexes/k)` клеток (компоненты/случайные клетки, поровну), остаток — нейтральный. Новые ИИ получают слоты в комнате (`slots.push`), уникальные имена через `randomCountryName`, `isAi: true`, `connId: null`.
  - Случайность: `Math.random() < 0.1`.
- У выбывшего обнуляется владение (все гексы либо нейтральные, либо отданы новым ИИ).
- Выбывший игрок остаётся в `players` с `eliminated = true` (действия отклоняются, доход 0).
- Валидации действий: `hasGameWinner` уже блокирует действия после победы; добавить блок для `eliminated`.

### Конец игры

- `computeWinner`:
  - прежнее правило: первый игрок с `hexCount > winHexCount(total)` — победитель;
  - новое правило: если все остальные игроки `eliminated` — победитель последний оставшийся (с hexCount > 0).
- Соло-режим: выбывание игрока-человека = немедленный конец игры: победитель — игрок, захвативший столицу (после обработки 90/10).
- Мультиплеер: игра продолжается, выбывший — зритель.

## 4. Отрезание территории

- После каждой смены владельца клетки (завершение битвы / захват) — проверяем территорию **потерявшего** эту клетку игрока (если он не выбыл):
  - находим связные компоненты его клеток (BFS по `NEIGHBOR_OFFSETS`, клетки в битвах учитываются по `ownerId`);
  - компонент, содержащий столицу — главный;
  - все остальные компоненты: `ownerId = null` (становятся нейтральными; битвы на них продолжаются как есть).
- Проверяется при смене владельца: и в `tickBattles`, и в `applyCapture` (нейтральная клетка без владельца не инициирует проверку — терять нечего; проверка нужна только если клетка ранее имела владельца).
- Взаимодействие с окружением: отрезанная нейтральная территория может быть захвачена через `applyEnclosure` окружившим её игроком — оставляем как есть (естественная награда).

## 5. UI (web)

- **Карта**: столица отмечена маркером (звезда) на гексе; в тултипе подпись «Столица».
- **HUD**: выбывшие игроки помечаются («выбыл», строка приглушена).
- **Баннер**: при выбытии игрока-человека — «Поражение: {победитель}».
- **Типы**: `Hex` получает `isCapital?: boolean`; `Player`/`ViewPlayer` получают `eliminated: boolean`.
- `isCapturable` блокирует действия выбывшего игрока.

## 6. Тесты

- Армия: конверсия процента в абсолютные значения (floor, минимум 1, 0 очков).
- Перезапуск: только aiMode; сброс состояния; новый генератор карты.
- Столица: первый гекс становится столицей; захват столицы = выбытие; 90% → нейтральная территория; 10% → деление на ИИ (2–5, поровну, остаток нейтральный).
- Отрезание: захват шейки → отрезанная часть без столицы нейтральна; часть со столицей не трогается; каскад (две шейки подряд).
- Конец игры: последний оставшийся = победитель; соло-выбытие = конец игры.
