# Дизайн: Этап 2 — настройка игры, комнаты, N игроков

Дата: 2026-08-11
Статус: утверждён пользователем

## Контекст

Сейчас в игре ровно 2 игрока и один игровой процесс на сервере (`GameService` —
синглтон, фазы menu/waiting/game), карта всегда 16×12 (192 гекса), победа = 97 гексов.

Этап 2 добавляет:
- выбор типа карты (5 типов, у каждого свой размер и вместимость);
- комнаты (лобби): создать/присоединиться, старт по кнопке хозяина;
- N игроков: люди + компьютеры вперемешку;
- режим «с компьютером»: 1 человек + N компов, без лобби, с паузой;
- победа = 50%+1 от числа гексов карты.

Этап 1 (новая механика сражений, тултипы, зум) — завершён, дизайн битв не меняется.

## Меню и лобби (web)

### Игра с компьютером
Меню → «Играть с компьютером» → экран настройки:
- тип карты (из списка ниже);
- количество компьютеров: 1..(maxPlayers − 1) для выбранного типа;
- кнопка «Начать» — игра стартует сразу (1 человек + N компов).
Пауза доступна (как сейчас).

### Игра с людьми
Меню → «Играть с людьми» → экран лобби:
- список открытых комнат: название, тип карты, заполненность (люди/макс), статус;
- кнопка «Создать комнату».

Создание комнаты:
- тип карты;
- макс. игроков (диапазон типа, по умолчанию — верхняя граница);
- компьютеры (рекомендуемое значение по умолчанию от типа карты);
- комната появляется в лобби, к ней присоединяются люди.

Экран комнаты (ожидание):
- список игроков (люди с именами + плейсхолдеры «Компьютер N»);
- кнопка «Начать игру» — только у хозяина (создателя);
- хозяин может стартовать при любой заполненности; компьютерные игроки добивают
  до maxPlayers;
- у не-хозяев — «ожидание хозяина»;
- «Выйти из комнаты» — покинуть лобби.

### Формула состава при старте
Игра всегда стартует полной: **компьютеров = maxPlayers − люди**. Настройка
«компьютеры» задаёт рекомендуемое значение в форме создания (выбранное значение
не ограничивает итоговый состав — свободные места добивают компьютеры).

## Сервер (архитектура)

- Вместо синглтона `GameService` — `RoomManager`:
  - `createRoom(hostConn, settings) → Room`;
  - `joinRoom(conn, roomId)`, `leaveRoom(conn)`, `startRoom(hostConn)`;
  - `listRooms(): RoomLobbyInfo[]` — открытые комнаты.
- Комната: `id`, `name` (автогенерируемое название страны), `mapType`,
  `maxPlayers`, `aiCount` (рекоменд.), `map` (hexes), `players[]`, `status:
  waiting | playing`, `hostPlayerId`.
- Один тик-луп перебирает все играющие комнаты (аналогично текущему циклу в
  `index.ts`); на каждой итерации — `applyIncome → tickBattles → applyEnclosure →
  AI-действия всех AI-игроков → computeWinner → persist не нужен`.
- WebSocket-сообщения: `create-room`, `join-room`, `leave-room`, `start-room`,
  `rooms` (состояние лобби), `room` (состояние комнаты). Существующие
  `start-ai`/`start-human`/`cancel-waiting` и фаза `waiting` удаляются.
- view/action-привязка: соединение → комната → `playerId` слота.

### БД

- Состояние игр **в память** (комнаты эфемерные, перезапуск сервера теряет
  активные игры — приемлемо для realtime-матча).
- Таблица `players` остаётся для идентичности (имена из Google-профиля).
- Убирается сохранение состояния гексов/очков (`gameRepository.persist` в тиках
  и действиях, `hexes`-таблица перестаёт использоваться; удалить из кода,
  схему можно оставить/почистить позже).
- `seedIfEmpty`/`ensureMines` — удалить (карты генерируются на комнату в памяти).

## Типы карт

| Тип | Форма | ~Гексов | Игроков (2..max) | Рекоменд. компов |
|---|---|---|---|---|
| Обычная | прямоугольник 16×12 (как сейчас) | 192 | 2–5 | 1 |
| Длинная | полоса 24×9 | 216 | 2–4 | 1 |
| Остров | овал (эллипс) с водой по краям | ~170 | 2–4 | 1 |
| Круглая | круг радиусом 9 | ~271 | 2–6 | 1 |
| Беларусь | контур страны на сетке (набор строк q-диапазонами) | ~190 | 2–5 | 1 |

Генерация:
- Обычная/Длинная: прямоугольник (cols × rows), как текущий генератор.
- Круглая: все гексы с hex-расстоянием от центра ≤ 9 (классический круг).
- Остров: гексы внутри эллипса (нормализованное hex-расстояние ≤ 1) — суша,
  остальное — вода (terrain = water).
- Беларусь: жёстко заданные диапазоны q по строкам r (контур страны,
  ~190 гексов).

Террейны внутри форм — как сейчас (случайный + шанс шахты на горах).

## N игроков (правила)

- `opponentId(state, playerId)` больше не нужен: все правила «соперника»
  становятся «любой другой игрок»:
  - атака: любой гекс любого другого игрока (соседний, минимум = стоимость);
  - битва за нейтральный гекс при захвате: создаётся, если у гекса есть
    соседний гекс любого другого игрока; защищать нейтральный гекс может любой
    соседний игрок;
  - окружение: существующая логика уже универсальна для N игроков.
- Первый гекс каждого игрока — бесплатно (правило `hexCount === 0` остаётся).
- Победа: первый игрок, достигший `floor(всего_гексов / 2) + 1` гексов
  (для 192: 97; для 271: 136; для 216: 109; для ~170: 86; для ~190: 96).
- Цвета игроков: палитра из 6 цветов по номеру слота (порядок вступления).
  В web заменить пару `PLAYER_COLOR.human/ai` на палитру `PLAYER_COLORS[i]`.
- AI: действует каждый AI-игрок один раз за тик; выбор цели — «ближайший
  соперник»/первый подходящий (логика этапа 1 остаётся: защита своего,
  оспаривание соседнего нейтрального, захват нейтралов, атака границы).

## Дисконнекты

- **Хозяин в лобби** (комната waiting): хозяином становится первый оставшийся
  игрок; если никого не осталось — комната удаляется.
- **Игрок во время игры**: слот навсегда занимает ИИ-замена; игроку
  засчитывается поражение (вернуться нельзя, его соединение закрывается).
- **Хозяин во время игры**: отдельной роли нет (хост = обычный игрок).

## Пауза

- Только в режиме «с компьютером» (1 человек + компы). В комнатах с людьми
  пауза недоступна (кнопка скрыта).
